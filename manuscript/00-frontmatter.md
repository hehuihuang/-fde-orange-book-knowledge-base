## 内容声明

本书所称 FDE，指 Forward Deployed Engineer，中文常译为“前线部署工程师”“前沿部署工程师”或“AI 落地工程师”。不同公司的岗位边界并不相同，本书讨论的是一组工作方式：工程师深入真实业务现场，端到端负责问题发现、技术范围、系统建设、生产上线、用户采用与经验产品化。

本书是独立原创的方法论手册。引用资料用于事实核验和延伸阅读，不复制既有中文 FDE 指南的章节结构或表述。所有监管内容仅作为工程风险提示，不构成法律意见；读者应结合业务所在地、行业规范和最新规则进行专业复核。

## 序章：为什么需要一本 FDE 橙皮书

大模型把“做出一个能说话的演示”变得很容易，却没有自动消除企业系统中最难的部分：数据散落在不同权限域，流程写在制度里却运行在人与人的默契里，成功指标由多个部门分别解释，安全和合规要求往往在上线前才被看见。一段漂亮的模型输出，距离可被员工每天依赖的生产系统，仍然隔着发现、设计、集成、评测、治理、运营和组织改变。

FDE 就站在这段距离之中。OpenAI 对该岗位的官方描述覆盖 discovery、technical scoping、system design、build 与 production rollout，并用生产采用、工作流影响和评测反馈衡量成功；Anthropic 的岗位描述进一步提到在客户系统中构建生产应用，以及交付 MCP Server、子智能体和 Agent Skills 等技术资产。二者共同说明：FDE 不是“去客户现场写代码”的同义词，而是对业务结果与工程闭环同时负责的角色。

本书提出一条贯穿全书的 **FIELD 交付环**：

1. **Frame｜界定问题**：还原真实工作，明确用户、约束和价值假设。
2. **Instrument｜建立度量**：定义基线、验收标准、评测集与风险阈值。
3. **Engineer｜构建系统**：用最小复杂度连接模型、数据、工具与业务流程。
4. **Launch｜生产落地**：完成安全评审、灰度、回滚、培训与运行保障。
5. **Diffuse｜扩散复用**：推动采用，把现场经验沉淀成产品、组件和组织能力。

这五步不是瀑布流程。任何一次评测失败、用户绕开或生产事故，都可能迫使团队回到前一步重新定义问题。优秀 FDE 的特征不是永远一次做对，而是让错误更早、更便宜、更可学习。

## 三条阅读路线

**准备转型 FDE**：先读第一、五、八篇，建立岗位认知与能力地图，再回到第三、四篇补齐交付和技术能力。

**正在交付项目**：从第二、三篇开始，直接使用附录模板；遇到 Agent、评测、安全和生产问题时查阅第四篇。

**搭建 FDE 团队**：重点阅读第一、六、七篇，用案例结构、团队指标和复用机制校准组织设计。
