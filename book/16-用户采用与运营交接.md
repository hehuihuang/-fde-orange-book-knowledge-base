# 第 16 章　用户采用与运营交接

系统上线之后，用户仍可能回到旧办法。要判断原因，需要观察实际工作中增加和减少了哪些动作。

## 使用入口影响采用成本

如果用户必须离开原系统、重新输入上下文，再把答案复制回去，节省的时间可能被这些动作抵消。尽量复用已有身份与工作入口，同时保持结果来源和当前状态可见。

信任来自持续可用的结果，也来自用户知道系统何时会失败。展示证据、标明信息缺口、允许修改与申诉，都有助于形成合理预期。用宣传替代质量，只会使下一次错误更难处理。

## 用真实任务判断采用

登录数能说明接触范围，不能证明工作改变。观察完成了多少任务、多少结果被修改、用户在哪里放弃，以及复核耗时是否下降。可以按部门、岗位和任务类型分开比较。

试点用户应包含愿意指出问题的人。他们可以帮助解释使用方法，但不应承担全部技术支持。身份异常、权限变化、模型故障和政策更新需要正式处理渠道。

## 把维护能力交给客户

| 交接对象 | 应能独立完成的工作 |
| --- | --- |
| 业务负责人 | 判断质量、调整允许任务、决定暂停 |
| 内容负责人 | 更新资料、处理冲突、撤回过期内容 |
| 技术负责人 | 查看运行状态、发布、恢复与排查 |
| 支持人员 | 收集问题、分类、升级并反馈结果 |

交接应通过一次实际演练检验。让维护人完成更新与回退，让支持人员处理一个模拟问题。说明文档能够被找到、读懂并用起来，才算真正交付。

## 本章练习

记录用户完成一项任务的全部操作，计算新系统额外增加了哪些步骤。再让一位未参与开发的人按运行手册处理一个小故障，补齐他无法继续的地方。
