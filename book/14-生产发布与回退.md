# 第 14 章　生产发布与回退

生产发布会把应用放进持续运行的业务环境。用户数量、数据分布与故障后果都可能超出原型条件，因此上线需要独立的检查。

## 一次发布包含哪些版本

代码之外，模型、提示、工具说明、索引和政策都可能改变行为。发布记录要能识别这组配置，出现问题时才能定位和恢复。只记代码提交号，常常无法复现当时的回答。

模型供应商更新、文档自动同步与权限调整也应有变更监测。外部条件变化后，核心评测需要重新运行。

## 逐步扩大影响范围

发布单位可以是指定用户、任务类型或流量比例。先选择风险可控且反馈及时的群体，设定观察窗口和暂停条件。扩大范围由实际证据决定，不只由计划日期决定。

| 上线检查 | 需要看到的证据 |
| --- | --- |
| 功能与质量 | 关键任务测试和风险切片结果 |
| 数据与权限 | 真实身份下的访问与越权测试 |
| 性能与费用 | 预期负载和费用上限测试 |
| 运行支持 | 监控、值班联系人与升级路径 |
| 回退 | 实际演练过的暂停和恢复办法 |

## 回退不能撤销一切

切回旧模型或旧代码，不能自动撤回已经发出的邮件、已修改的订单或已形成的客户承诺。写操作需要单独的核对与补偿方案，并由获授权人员决定是否执行。

因此，回退计划要分开两件事。先停止继续产生影响，再确认已经发生的变化。事故记录保留受影响对象、动作时间和当前状态，便于业务负责人处理。

## 本章交付物

完成一份发布记录与回退演练记录。模拟模型质量下降、工具不可用和权限异常，检查团队能否在不依赖原开发者的情况下暂停相关功能，并继续办理必要业务。
