# 第 23 章　TIME，在固定期限内交付

与持续演进的内部系统相比，围绕媒体发布的项目往往有明确日期。上线时间固定时，工程团队需要控制功能范围，并安排每一部分的验收。

## 公开事实与证据

Scale AI 的 TIME 案例介绍了围绕 2024 年年度人物内容的互动体验，包括文本与语音交互、多语言能力，以及基于 TIME 内容的问答。发布方称项目从提案到生产用时不到两个月，并进行了包含约 7,000 条攻击向量的测试。

证据等级为 A，来自服务商客户故事。测试数量只能说明公开材料报告的工作量，不能证明所有攻击均被阻止，也不能替代质量结果。

## 多种能力需要分别验收

以下为本书分析与教学设计，证据等级为 D。文字回答正确，不意味着语音转写、翻译与播放都正确。应分别检查内容、语言、音频和界面，再测试用户从提问到获取答案的完整过程。

| 任务 | 应独立检查的内容 |
| --- | --- |
| 内容问答 | 引用是否支持回答、是否越出材料范围 |
| 多语言 | 人名、专名与语义是否保持一致 |
| 语音输入 | 噪声与识别错误怎样处理 |
| 语音输出 | 播放失败时是否仍可读文字 |
| 发布页面 | 流量、延迟与不可用时的提示 |

## 固定期限下的取舍

明确必须上线的体验，再设置可以取消的功能。若某种语言来不及完成合格审校，缩小支持范围比在发布时隐藏质量风险更稳妥。

同时准备分层回退。语音不可用时保留文字，互动服务不可用时仍让读者访问原文。这样的设计减少单个依赖故障对内容阅读的影响。

内容授权也要在开发前确认。可以读取公开网页，不代表可以任意训练、复制或商业改编其中内容。项目需要按实际许可确定可用范围。

## 上线范围怎样形成依赖关系

以下是作者设计的媒体互动教学项目，工期与功能均为假设。最低可用版本只提供原文入口、已审查的静态摘要与文字问答。语音输入依赖转写，语音播放依赖合成音频，多语言依赖内容及术语审校。把这些依赖列清以后，团队才能判断删掉一个功能是否真的减少关键路径。

| 交付项 | 前置条件 | 验收失败时保留什么 |
| --- | --- | --- |
| 静态摘要 | 内容授权与编辑审查 | 原文入口 |
| 文字问答 | 可用内容集与引用测试 | 已审查摘要 |
| 新增语言 | 术语表、母语审校及界面适配 | 已验收语言 |
| 语音输入 | 转写质量、权限与超时处理 | 文本输入 |
| 音频播放 | 音频可用、播放错误处理 | 屏幕文字 |
| 互动服务 | 容量、错误提示和服务开关 | 静态页面 |

在固定发布日期前，依赖内容审校的工作往往无法单纯靠增加工程师缩短。可以先固定允许问答的文章集合与版本，后续内容更新走轻量但明确的复核。若发布当天仍不断更改材料，又没有跑完引用与语言回归，团队实际发布的是未验收版本。

## 多模态链路的延迟账

假设一次语音任务含上传、转写、检索、回答生成和音频生成。串行路径下，端到端延迟等于这些阶段及队列等待的总和；阶段可并行时，需按实际依赖关系计算关键路径。用户第一次看到文字的时间，与音频开始播放的时间应分别测量。

教学演算中，转写一秒、检索半秒、生成两秒、音频生成一秒，串行处理约四点五秒，尚未计算网络和排队。这里没有真实供应商性能承诺。若先显示文字再生成音频，文字完成时间缩短，但音频最终完成时间未必减少。报告“响应更快”以前，要说清测的是哪个事件。

设置总体截止时间后，各阶段获得可用预算。检索超时返回安全提示或已审查内容，不能为了赶时间直接让模型编答案。语音识别对人名不确定时，可以显示识别文本让用户修正，避免错误一路进入翻译和回答。

## 攻击向量数量怎样变成覆盖说明

七千条测试可以来自少数模板的重复，也可以覆盖多种任务与语言，单个计数无法区分。教学项目可以按攻击入口、目标、语言和预期阻断点登记。文档内注入、用户诱导越界、伪造编辑指令与引用欺骗具有不同路径，不能都归入一句“安全测试通过”。

| 教学测试 | 观察点 | 安全行为 |
| --- | --- | --- |
| 原文夹带要求忽略规则 | 内容与指令是否分离 | 内容不能改写服务权限 |
| 询问材料以外的事实 | 范围识别与引用 | 说明范围并引导原文查阅 |
| 翻译后省略限定词 | 多语言含义一致性 | 保留影响判断的限制 |
| 假冒编辑要求变更报道 | 身份与授权边界 | 不执行业务变更 |
| 音频服务不可用 | 回退与用户提示 | 文字仍可阅读 |

测试还要记录成功率、严重程度和未解决类别。公开报告未给出这些项目时，读者应保留未知；自己的交付报告则应该让负责人知道剩余风险和上线后的观察方案。

## 上线演练与内容冻结

作者建议教学项目在发布前安排一次完整演练。用冻结的内容版本部署，核对内容授权、语言选择、引用跳转、错误页面和开关权限。再模拟回答服务不可用与音频不可用，确认静态内容可以独立访问。演练记录包含使用的版本、检查人和未解决问题。

发布窗口中的紧急内容修订需要区分事实修正与文案润色。事实修正影响答案与引用，必须进入快速回归；即使只改标点，也要检查引用锚点是否变化。紧急发布流程可以缩短等待，不能让受影响的质量检查消失。

## 读者实作与复盘

为五种功能画依赖表，选出最小可用范围，写清每种故障下用户仍能做什么。再设计三条跨语言测试，让人名、否定词和日期分别成为关键检查点。

答案应让静态原文不依赖模型服务，保留文本输入与文字输出，并明确未审校语言不会悄悄上线。交付速度的来源应落在范围与依赖管理，不能从一个客户案例推定所有项目都能两个月完成。

## 可复用的 FDE 工作包

准备功能优先级、语言与能力测试表、内容授权记录和回退方案。安排一次上线演练，逐个关闭依赖，观察用户是否仍能完成最低限度的阅读任务。

## 资料没有说明什么

材料未给出完整用户规模、转化数据、全部测试结果与长期运营成本。不到两个月的交付时间不能直接用作其他项目的工期承诺。
