# 第 23 章　TIME，在固定期限内交付

与持续演进的内部系统相比，围绕媒体发布的项目往往有明确日期。上线时间固定时，工程团队需要控制功能范围，并安排每一部分的验收。

## 公开事实与证据

Scale AI 的 TIME 案例介绍了围绕 2024 年年度人物内容的互动体验，包括文本与语音交互、多语言能力，以及基于 TIME 内容的问答。发布方称项目从提案到生产用时不到两个月，并进行了包含约 7,000 条攻击向量的测试。

证据等级为 A，来自服务商客户故事。测试数量只能说明公开材料报告的工作量，不能证明所有攻击均被阻止，也不能替代质量结果。

## 多种能力需要分别验收

以下为本书分析与教学设计，证据等级为 D。文字回答正确，不意味着语音转写、翻译与播放都正确。应分别检查内容、语言、音频和界面，再测试用户从提问到获取答案的完整过程。

| 任务 | 应独立检查的内容 |
| --- | --- |
| 内容问答 | 引用是否支持回答、是否越出材料范围 |
| 多语言 | 人名、专名与语义是否保持一致 |
| 语音输入 | 噪声与识别错误怎样处理 |
| 语音输出 | 播放失败时是否仍可读文字 |
| 发布页面 | 流量、延迟与不可用时的提示 |

## 固定期限下的取舍

明确必须上线的体验，再设置可以取消的功能。若某种语言来不及完成合格审校，缩小支持范围比在发布时隐藏质量风险更稳妥。

同时准备分层回退。语音不可用时保留文字，互动服务不可用时仍让读者访问原文。这样的设计减少单个依赖故障对内容阅读的影响。

内容授权也要在开发前确认。可以读取公开网页，不代表可以任意训练、复制或商业改编其中内容。项目需要按实际许可确定可用范围。

## 可复用的 FDE 工作包

准备功能优先级、语言与能力测试表、内容授权记录和回退方案。安排一次上线演练，逐个关闭依赖，观察用户是否仍能完成最低限度的阅读任务。

## 资料没有说明什么

材料未给出完整用户规模、转化数据、全部测试结果与长期运营成本。不到两个月的交付时间不能直接用作其他项目的工期承诺。
