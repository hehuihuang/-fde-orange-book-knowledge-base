# 阅读说明

企业购买了模型服务，项目仍有很多事情要做。业务人员的任务要重新梳理，散落在系统里的资料要能被正确调用，模型给出的结果要有人验收，出错以后还得有办法继续工作。FDE 的工作就在这些具体环节里。

本书把 FDE 译为前线部署工程师，英文为 Forward Deployed Engineer。不同公司的岗位名称和职责并不完全一致。本书用它指代一种靠近客户业务、参与构建并持续对交付结果负责的工程工作方式。

这次编写重新核对了企业官方案例、工程文档、公开培训课程和 Datawhale 的实践材料。事实能够支持到哪里，案例就写到哪里。没有公开的团队人数、架构细节和经济结果，不用推测补齐。

## 怎样读这本书

全书分为四篇。第一篇建立岗位与业务认知，并从对象、事件、状态与成本进入工程设计。第二篇深入模型推理、上下文、数据合同、检索、Agent 控制、统计评测与安全。第三篇沿着项目推进学习交付方法。第四篇先用八个海外企业案例和四个中国 FDE 案例检查方法，最后通过原创项目走完设计、实现、测试和交接。

有工程经验的读者可以重点读第 2、3、11、12、16、17 章。业务负责人可以先读第一篇，再读需求发现、范围、采用与交接。刚接触 AI 的读者应把第二篇的术语和流程图读熟，不必一次学会所有工具。

每章提出具体问题，解释必要概念，给出可以执行的工作方法，并留下一项练习或交付物。公式旁标明假设和适用范围。短代码标明它已经实现的部分及缺少的生产能力。练习属于本书设计的教学任务，不代表任何公司的真实内部流程，也不构成医疗、金融、法律或安全合规建议。

第二篇可以配合最后一章阅读。先理解一项机制，再在物料与采购助手中寻找它的落点。数量、单位、权限、对象版本、审批和幂等都有可观察结果。阅读技术方案时，尝试提出一个让它失败的输入，再追问系统能否检测与恢复。

## 最后项目能做什么

第 27 章对应仓库的 `examples/material_assistant/`。这是本书原创的离线教学工程，使用 Python 标准库与 SQLite，数据为合成数据。读者可以运行示例和测试，不需要购买模型服务或提供密钥。离线规划器使用确定性逻辑，不能将它的结果解读为大模型智能的实测。第 28–31 章整理破局社区公开的 FDE 案例，并分别标明作者陈述、公开事实和本书分析。

项目保留数据、检索、草稿、审批、写入与审计的边界，便于替换真实接口。接入模型只改变提案生成方式，授权与事务仍由应用负责。项目没有接入真实 ERP，也没有外部身份服务、生产级部署和独立安全审计。完成练习说明读者验证了一组教学机制，不能直接把项目用于真实采购。

本版以增加原理、推演、反例与实作扩展内容。页数来自实际章节排版，使用正常字号与行距，章节切换页和目录计入总页数。每章可以独立查阅，阅读版还提供可展开的本章目录。PDF 中较长代码行会视觉折行，复制运行时以章节 Markdown 和配套源文件为准。

## 怎样读案例

本书用 A、B、C、D 区分材料性质。A 为企业官方资料或正式文件，B 为有编辑核验的媒体报道，C 为社区或社交平台自述，D 为本书的分析与教学设计。A 表示来源直接，不表示结果经过独立审计。

案例的价值在于让读者看见工程问题怎样与业务相连。采用人数、节省时间、自动化率各有统计范围。它们不能相互替代，也不能直接换算成收益或岗位减少。特别是供应商发布的成功故事，应当连同其未披露的信息一起阅读。

## 关于版本与资料

新版书名统一为《FDE橙皮书》，副标题为《从业务现场到 AI 系统交付》。章节 Markdown 是内容来源，PDF 和阅读版从同一份章节生成。旧书稿和研究文件保留用于追溯，不再充当主目录。

本版研究李博杰的 AI Agent 开源书、范冰的 FDE 指南和 Awesome FDE Roadmap，用它们检查主题覆盖与学习路径。具体机制回读原始论文、官方协议、数据库文档和工程资料。本书自行组织章节、设计演算与编写代码，不沿用参考项目的段落、专有比喻或代码。范冰指南的商业改编需要作者书面授权，本书没有进行该种改编。

国内案例保留 Datawhale 原始链接。推荐课程不构成培训机构背书，完成课程也不等同于具备生产交付能力。知识与软件都会变化，调用接口、许可证、价格及协议应在实际项目开始时重新核对。
