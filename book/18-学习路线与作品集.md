# 第 18 章　学习路线与作品集

学习 FDE 可以围绕一项小型交付展开。课程提供概念和练习，作品则检验你能否处理需求、数据、失败和交接。两者需要结合。

## 按缺少的能力选择课程

下列入口在本次编写时已核查。课程开放方式、费用、账号与证书条件可能变化，应以官方页面为准。本书不承诺就业或认证结果。

| 学习目的 | 官方资料 | 学完后应留下什么 |
| --- | --- | --- |
| 业务对象与用例界定 | Palantir AIP 入门与 Scoping Use Cases | 一页用例与对象关系图 |
| 理解 Agent 的运行方式 | Hugging Face Agents Course | 带工具与停止条件的小应用 |
| 选择简单工作流 | Anthropic 工程文章 | 一份架构取舍说明 |
| 调试与评测 Agent | DeepLearning.AI 与 Arize 课程 | 测试集、评分器与实验报告 |
| 理解接口连接 | MCP 官方文档 | 工具接口与权限说明 |

Palantir 的入门路线连接用例界定与实际工作流，适合学习平台如何服务业务。Hugging Face 课程包含框架和实践任务，适合具备基础 Python 能力的读者。DeepLearning.AI 的评测课程覆盖可观测性、组件评测与结构化实验。只完成其中一项，仍不足以证明可以独立交付生产系统。

## 一条可调整的学习安排

第一阶段观察真实任务并取得合法样本，留下流程、基线与权限范围。第二阶段完成最小应用，把数据、检索或工具调用接起来。第三阶段建立测试与运行记录，故意模拟失败。最后请其他人试用，并完成交接说明。

可以按自己的可用时间安排，不必把某个固定天数当作能力保证。每一阶段的出口由作品决定。应用能够运行但没有评测，就继续补评测；演示顺利但用户无法自行使用，就继续改交互和说明。

## 作品集应该让人核查

一份有说服力的作品集包括问题背景、授权范围、方案取舍、运行方法、失败样本和结果限制。演示视频可以辅助理解，但要说明哪些部分为模拟数据，哪些已经实际验证。

公开发布时，不上传客户数据、凭据、私人会议或未授权材料。可以用明确标注的合成数据展示技术流程，但不能据此声称取得了真实业务收益。

## 怎样使用 X 与社区

X 适合发现招聘、工程师讨论和新材料。本次检索到 Speechmatics 发布过包含 FDE 的岗位信息。这能作为岗位线索，不能用于推算行业规模或平均薪酬。看到效果数字后，应继续寻找公司原文、技术说明或正式文件。

国内实践可从 Datawhale FDE100 开始。范冰的公开 FDE 指南也值得作为延伸阅读，但其版权声明限制商业用途。本书只链接原作。

## 从可复现的任务检验学习成果

本章核对了课程入口，并阅读用户推荐的 Awesome FDE Roadmap 和范冰的公开指南。Roadmap 采用 MIT 许可，主题覆盖数据、架构与客户协作；范冰指南限定免费阅读及非商业分享，商业用途需书面许可。本书只将它们作为延伸阅读线索，不复制其正文、代码或课程结构。

下面的路线和作品评分由作者编排，围绕一项合法的小任务完成。可以直接选择本书最后一章的物料项目，也可以选择其它任务。合成数据演示与真实业务验证分开标注，作品规模不作为生产能力证明。

第一项成果是问题与数据说明。写触发事件、对象、状态和失败路径，整理字段、单位、权威来源及授权。第二项成果是有异常路径的实现，完成身份、查询、理解、校验和结果保存。第三项成果是评测与运行证据，固定样本和版本，记录失败与恢复。第四项成果是交接，要求他人按说明重现并处理一个故障。

| 学习提交 | 最低内容 | 离开该阶段的条件 |
| --- | --- | --- |
| 问题及数据 | 流程、范围、字段与样本合法性 | 能说明正确结果及主要未知 |
| 请求链实现 | 可启动应用及异常处理 | 正常和关键反例都有可见结果 |
| 评测及运行 | 评分、版本、日志和演练 | 新改动可以重复比较 |
| 采用及交接 | 操作说明、支持和限制 | 他人能重现并说明未覆盖范围 |

## 技术学习按具体缺口展开

软件基础先掌握数据结构、函数、测试、错误处理和 HTTP 请求。SQL 学习包括关联、过滤、索引以及事务，能够解释一条查询读到了什么。身份与权限学习区分认证和授权，能够测试不同身份访问不同对象。具备这些基础后，模型与 Agent 的工具使用才有可信执行环境。

模型部分围绕输入、上下文和结果校验。检索部分围绕记录、索引、权限过滤及引用。工具部分围绕参数、语义、超时与幂等。评测部分围绕样本、评分与误差。不要仅凭框架调用成功就结束学习，沿着每次请求观察实际状态，发现哪个机制还解释不清。

一种有用的深入练习是不用复杂框架做一次小实现。例如用标准程序实现状态机与只读工具，再接一个明确标注的模拟理解适配器。读者可以先测控制与数据行为，再在获得合规调用条件后测试真实模型。模拟路径不提供模型能力证据，却能够帮助分清系统责任。

## 课程资料怎样转成自己的实验

Palantir 的入口将用例界定与平台工作流连接，Hugging Face 课程提供 Agent 概念与实践，Anthropic 文章讨论工作流和 Agent 的取舍。DeepLearning.AI 的评测入口提供评测学习方向，MCP 官方文档帮助理解工具连接协议。每份资料都只覆盖能力的一部分。

读完后提出自己的问题并设计实验。阅读上下文资料以后，可以比较证据数量变化与引用错误；阅读工具协议以后，可以实现一个明确语义的只读操作并测试越权；阅读评测以后，可以让两位评分者独立标注同一批样本并整理分歧。结果包括失败，才便于他人判断理解深度。

培训时间、结业证明或课程数量不能直接预测就业结果。课程条件会变化，用户选择前应回读官方开放及付费说明。本书不提供薪酬保证，也不将社区路线的某项强制时间表作为能力标准。

## 作品集提供能核查的证据

一个公开项目可以有首页说明、运行说明、架构决定、数据字典、测试集说明、实验报告和运行手册。首页写清任务与范围，运行说明写清前置条件与启动步骤，架构决定解释备选，实验报告保留样本口径与失败，手册说明停止与恢复。

| 作品材料 | 审阅者能够核查 | 不应夸大的结论 |
| --- | --- | --- |
| 合成数据演示 | 代码及规则在教学输入上成立 | 已获得真实客户效果 |
| 离线评测 | 固定样本与版本的质量 | 已适应所有生产流量 |
| 故障演练 | 限定故障可以安全接管 | 不会出现其它故障 |
| 他人重现 | 说明足以支持当前环境复现 | 已完成所有客户环境部署 |
| 用户试用 | 获授权范围的动作与反馈 | 已证明长期财务收益 |

公开材料不放凭据、客户全文、私人会议或员工个人信息。需要展示真实效果时取得许可，注明时间、样本、分母及发布方归属。使用模型生成的数据也明确标注，不能作为真实用户调查结果。

## 用审阅与答辩暴露薄弱处

请审阅者从空白环境启动项目，随后换一条正常输入、一个缺失字段和一次依赖故障。原作者只观察并记录。审阅者无法继续的位置就是下一次改进目标。不同操作系统或服务环境没有测过时，说明支持边界。

答辩可以围绕六个问题。为什么选择这项任务，为什么需要模型，正确结果怎样判断，数据和动作如何授权，最严重错误怎样停止，以及你离开后谁能维护。每个答案应指向一个工件或实验。不能给出证据的部分，写进下一步计划，不用术语补空缺。

## 社区资料先找到出处再形成判断

X 的招聘与工程讨论可帮助发现线索，后续应查公司岗位页、官方说明或论文。岗位名称不能直接证明企业采用规模，自述效率不能直接证明利润。Datawhale 的社区案例适合寻找具体任务及失败讨论，效果仍以原报告口径理解。

读参考书时记下主题及原出处，再用自己的问题、例子和验证过程重新组织。遇到版权限制，保留阅读链接，避免逐章改写或复制例子。本书的路线强调独立实现和证据积累，最终成果由读者实际完成的任务检验。

## 作品评分先区分解释、验证与维护

作者设计的审阅规则可以将每项能力记为未提供证据、能够解释、能够验证或能够维护。分数只是索引，必须附对应工件。能够解释身份传递但没有越权反例，可以通过解释项，不通过验证项；有测试但不知如何停机，仍缺维护项。

审阅者选择一个作品中的主张追到底。若作者说重复请求安全，就运行并发及响应中断测试，查看是否保持同一结果。若作者说引用可靠，就回读原材料与版本。发现限制以后，把支持范围写清楚，比用一个总分遮住薄弱项更有说服力。

最后一次提交包含当前证据和下一步未知。新的学习计划从未知出发，要求形成下一项可核查工件。作品已经支持的能力与尚未验证的能力同时可见，读者也能据此判断是否需要继续深入某个基础主题。

## 本章交付物

把学习计划改写成四次可展示的提交，每次说明新增了什么能力和证据。最后请别人从空白环境复现项目，记录他遇到的问题并修正。

参考答案应包含流程与字段、实现与反例、评测与演练、交接与限制四次提交。若只有界面截图、框架介绍及成功视频，继续补异常输入、评分规则和他人重现。每项未来建议都明确尚未完成，不把计划写成能力证明。
