# 第 19 章　Airbus，让数据进入维修决策

航空运营把设备、维护记录与人的判断联系在一起。Skywise 适合放在案例篇开头，因为它提醒读者，FDE 的工程工作早于本轮大模型应用，也不局限于聊天界面。

## 公开事实与证据

Airbus 在 2017 年发布 Skywise，公开介绍了与 Palantir 合作的数据平台。平台将航空公司运营、维修与飞机相关资料联系起来，支持航空运营与维护分析。早期材料列出 AirAsia、Delta、easyJet 等采用方。

证据等级为 A，来自企业发布材料。不同年份的采用规模与收益数字属于不同范围。本章不把它们合并成统一效果，也不把平台部署全部归因于某个岗位。

## 业务问题怎样形成工程问题

维修判断涉及具体飞机、部件、故障记录与处理状态。不同系统中的名称和时间不能正确对应，分析人员就难以判断资料是否描述同一事件。能够连接数据，只解决了传输；业务对象和关联关系决定了数据能否一起解释。

下面是本书的分析与教学设计，证据等级为 D，并非对客户内部架构的披露。

若为类似任务设计试点，可以选择一种设备和一种异常。先整理历史记录的标识、时间与维修结果，再请专业人员定义什么情况需要检查。系统提供证据与提示，获授权人员仍负责实际维修决定。

| 交付环节 | 应确认的事情 |
| --- | --- |
| 数据匹配 | 设备、部件与事件是否正确关联 |
| 异常判断 | 误报和漏报分别造成什么影响 |
| 工作安排 | 提示能否提前进入维护计划 |
| 结果回写 | 处理结果能否回到后续分析 |

## 为什么要关注工作安排

即使某种异常能够被识别，组织仍需要人员、备件和时间来处理。试点应检查提示到达后是否发生了正确行动，以及提前量是否足够。单独报告检测准确率，无法说明运营价值。

反过来，某次运营改善也可能同时受到排班、供应和维护政策变化影响。需要保留这些条件，避免把全部变化算给模型或平台。

## 设备身份与事件顺序的教学推演

本节使用作者设计的合成设备记录。假设两份记录都写着部件 P-17，一份属于设备 A 的历史拆下件，一份属于设备 B 的当前安装件。将部件名称作为唯一键，查询会把两段历史拼在一起。稳定标识还需要序列号，安装关系则需要有效起止时间。设备与部件各自存在，安装关系可以改变，不能把所有属性压在一张永远覆盖的设备表里。

| 对象或关系 | 最少字段 | 必须保持的约束 |
| --- | --- | --- |
| 设备 | 设备 ID、运营主体 | 跨主体查询有明确授权 |
| 部件 | 部件 ID、型号、序列号 | 型号不能替代实例身份 |
| 安装关系 | 设备 ID、部件 ID、生效区间 | 同一实例的当前安装关系无冲突 |
| 观测事件 | 事件 ID、事件时间、接收时间 | 重发事件不产生重复观测 |
| 处置记录 | 建议 ID、审核人、结果 | 建议、批准和实际完成分开 |

事件时间描述事情发生的时间，接收时间描述系统获知的时间。离线设备晚传记录时，这两个时间可能相差很大。按接收时间画趋势，容易把旧事件看成刚发生；只按事件时间处理，又需要明确允许迟到多久，以及迟到数据能否改变已经发布的分析。本书建议把原始事件保留，衍生结果记录计算版本，修订时说明变化来源。具体保留期限由实际项目政策决定。

关系有效区间可以约定为左闭右开，即起点包含、终点不包含。这样一次拆装的交界时刻归属唯一。若源系统只记录日期，项目就缺少当天精确顺序。此时应暴露时间精度限制，避免补造分钟级安装历史。

## 从异常分数到可执行建议

异常检测产生的分数还需要经过业务判断。本书为教学设定三条处理路径。资料缺失的记录进入数据核对队列；资料完整但证据弱的记录只做观察；达到专业团队定义条件的记录形成检查建议。分数阈值的选择必须结合误报与漏报的代价，没有行业通用的安全阈值。

以合成的每日一百条提示演练。若工作人员只能审核二十条，按分数取前二十条是一种调度策略，却会遗漏低分、高后果的事件。可以把专业团队定义的高后果规则作为独立优先级，再在剩余容量内排序。若规则之间冲突，系统记录冲突并交给负责人判断，不把冲突藏进一个综合分数。

衡量建议是否有用，至少要记录生成、阅读、接受、执行和结果核对几个时点。建议提前三天生成，但负责人直到最后一天才看到，不能把三天全算成有效提前量。实际执行还受备件和人员约束；检测团队与运营团队需要一起复盘这些等待。

## 数据故障怎样与模型故障分开

可以设计一次迟到事件演练和一次安装关系冲突演练。前者检查结果能否修订以及审核人是否收到变化提示；后者检查系统是否停止合并相关记录。如果异常分数看起来正常，关键对象关联仍然错误，试点也不能过关。

另一种反例是测试数据全部来自同一设备型号，生产部署却覆盖新型号。需要先确认传感器含义、采样频率和维护政策的差异，再判断模型或规则是否适用。建立型号切片的目的在于显示适用范围，样本少的切片应显示证据不足，不能用总体准确率盖住它。

## 读者实作与复盘

用六条合成事件构造一段安装历史，至少包含一次换装、一条重发和一条迟到。写出每条观测应关联的部件实例，列出系统能确定和不能确定的关系。答案应按事件时点检查有效区间，按事件 ID 消除重复，并保留迟到信息；若两个有效区间重叠，应给出冲突结果。

再把建议交付记录做成一张小表，计算生成到阅读、阅读到执行两段用时。思考只优化模型分数是否能够改变第二段用时。这个练习检验的是对象、时间与组织动作之间的联系，不要求重建航空生产系统。

## 可复用的 FDE 工作包

准备设备对象字典、事件关联规则、异常样本表和处置记录。以一个范围有限的场景演练从数据到行动再到结果回写的过程。涉及航空安全的系统应接受相关专业审查，本书练习只能使用获授权的非生产数据。

## 资料没有说明什么

公开材料没有给出所有航空公司的具体实现、人员投入、维护成本和独立因果评估。读者不能据此推定任何相似组织都会获得相同收益。
