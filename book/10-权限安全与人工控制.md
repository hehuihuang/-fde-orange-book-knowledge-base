# 第 10 章　权限、安全与人工控制

当模型只能生成建议时，错误主要通过用户采纳影响工作。模型获得工具之后，错误可能直接改变记录或触发外部动作。控制措施应跟着这种影响变化。

## 按动作判断风险

读取公开资料、读取敏感数据、草拟内容、修改内部记录和对外执行，风险并不相同。应用应针对每一种动作定义授权与确认。不能因为用户可以打开应用，就允许它代表用户完成所有操作。

高影响动作要在执行位置设置控制。确认界面应显示对象、金额或范围、预期变化和是否可撤销。若用户看不到这些信息，确认按钮只能留下形式上的记录。

## 提示注入的信任边界

网页、文档、邮件和工具结果都可能夹带要求模型忽略规则或传出信息的内容。这些材料是待处理数据，不能赋予它们与用户授权相同的地位。

防护需要多层配合。限制工具权限、校验参数、隔离敏感数据、控制外部发送目标，以及记录高风险动作，都能缩小影响。单独加一句「不要受恶意指令影响」无法替代这些工程控制。

## 人工复核需要工作条件

复核者要获得证据、足够时间和拒绝权限。若每天要确认大量无法核查的结果，人工控制容易退化成机械点击。系统应把需要判断的差异呈现出来，并允许回到原始资料。

| 控制问题 | 应有的明确答案 |
| --- | --- |
| 谁能读取 | 用户、角色、租户与对象权限 |
| 谁能执行 | 动作授权、额度和确认条件 |
| 何时停止 | 异常、缺证据、预算耗尽等条件 |
| 出错后怎么办 | 接管人、暂停方式和记录核对 |
| 数据保留多久 | 内容分类与组织保留政策 |

## 安全验收应包含失败路径

测试越权查询、跨租户访问、恶意文档、参数篡改和重复提交。检查失败时是否泄露敏感细节，是否仍然产生了副作用。安全团队给出要求后，应把可自动检查的部分纳入持续测试。

本章仅提供工程检查思路。具体行业、地区与合同要求，需要组织的专业人员审核。没有通过对应审查，不能声称应用已经合规。

## 本章交付物

为项目列出一份动作权限表和失败测试表。选一个最高风险动作，完整演练用户拒绝、请求超时与人工接管，确认系统状态可以解释。
