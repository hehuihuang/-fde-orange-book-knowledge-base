# 第 21 章　Morgan Stanley，把评测放进开发

知识助手与会议纪要看起来都是文字任务，验收重点却不同。前者要准确找到和解释证据，后者要完整记录重要信息与待办，不能擅自增加承诺。

## 公开事实与证据

OpenAI 与 Morgan Stanley 的案例介绍了内部知识助手和 Debrief 会议工具。团队在部署前使用领域评测，并持续检查结果。Debrief 在取得客户同意后处理会议录音，生成笔记及后续草稿，由顾问复核。发布方报告超过 98% 的顾问团队使用内部助手。

证据等级为 A，来源为联合客户故事。采用比例反映该材料的统计口径，不能直接证明收入提升或每条回答正确。

## 评测为什么需要分任务

以下是本书的分析与教学设计，证据等级为 D。知识问答应检查资料是否相关、引用是否支持结论，以及用户是否具有访问权。会议工具还要检查参与者、行动负责人、约定日期与待确认事项。

同一句含糊表达，在检索任务里可能需要补问，在会议纪要里则应保留不确定性。把两种应用交给同一个笼统的「回答质量」评分器，会掩盖重要区别。

| 应用 | 应优先检查的失败 |
| --- | --- |
| 知识检索 | 旧政策、错误引用与越权资料 |
| 会议笔记 | 漏掉限制、错认人物和虚构行动项 |
| 后续草稿 | 添加未经同意的承诺 |
| 系统写入 | 重复记录与错误关联客户 |

## 把顾问的修正用于改进

用户修改输出可以形成有价值的反馈，但需要分类。修正事实与调整语气的意义不同。将所有编辑都当成模型错误，会使评测目标变得混乱。

记录修改原因后，可以形成新的测试样本。仍需检查是否获得数据使用许可，并去掉不必要的客户信息。测试集中的敏感资料也需要权限与保留规则。

## 可复用的 FDE 工作包

准备两套分别面向问答与会议的评测表，定义严重错误、人工确认与写入规则。用模拟材料完成「草稿、复核、确认、写入」的演练，检查取消和重复提交两条路径。

## 资料没有说明什么

客户故事没有提供完整评测集、所有阈值、成本与独立对照。公开方案也不构成对金融机构数据或业务合规的通用承诺。
