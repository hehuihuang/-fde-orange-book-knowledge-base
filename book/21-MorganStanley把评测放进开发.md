# 第 21 章　Morgan Stanley，把评测放进开发

知识助手与会议纪要看起来都是文字任务，验收重点却不同。前者要准确找到和解释证据，后者要完整记录重要信息与待办，不能擅自增加承诺。

## 公开事实与证据

OpenAI 与 Morgan Stanley 的案例介绍了内部知识助手和 Debrief 会议工具。团队在部署前使用领域评测，并持续检查结果。Debrief 在取得客户同意后处理会议录音，生成笔记及后续草稿，由顾问复核。发布方报告超过 98% 的顾问团队使用内部助手。

证据等级为 A，来源为联合客户故事。采用比例反映该材料的统计口径，不能直接证明收入提升或每条回答正确。

## 评测为什么需要分任务

以下是本书的分析与教学设计，证据等级为 D。知识问答应检查资料是否相关、引用是否支持结论，以及用户是否具有访问权。会议工具还要检查参与者、行动负责人、约定日期与待确认事项。

同一句含糊表达，在检索任务里可能需要补问，在会议纪要里则应保留不确定性。把两种应用交给同一个笼统的「回答质量」评分器，会掩盖重要区别。

| 应用 | 应优先检查的失败 |
| --- | --- |
| 知识检索 | 旧政策、错误引用与越权资料 |
| 会议笔记 | 漏掉限制、错认人物和虚构行动项 |
| 后续草稿 | 添加未经同意的承诺 |
| 系统写入 | 重复记录与错误关联客户 |

## 把顾问的修正用于改进

用户修改输出可以形成有价值的反馈，但需要分类。修正事实与调整语气的意义不同。将所有编辑都当成模型错误，会使评测目标变得混乱。

记录修改原因后，可以形成新的测试样本。仍需检查是否获得数据使用许可，并去掉不必要的客户信息。测试集中的敏感资料也需要权限与保留规则。

## 两类任务的样本设计

下面使用作者设计的政策问答与会议文本，不涉及客户资料。问答样本除问题外，还要保留可访问文档版本、预期证据、必须提及的限制和允许拒答的情况。会议样本则保留转写、说话人映射、预期行动项以及禁止补写的承诺。两套样本可以使用相同的身份服务和审计框架，业务标签仍分开维护。

| 教学样本 | 关键检查 | 严重失败示例 |
| --- | --- | --- |
| 同名政策的两个版本 | 生效日与适用对象 | 用已失效规定回答当前问题 |
| 文档含限制条件 | 结论与限制绑定 | 引用原文却省略例外 |
| 用户无权读附件 | 检索和展示均隔离 | 回答泄露附件内容或标题 |
| 两人讨论同一行动 | 人物与动作正确对应 | 把建议者当成承诺执行者 |
| 行动日期尚未确定 | 保留未定状态 | 自动填写具体截止日 |
| 草稿确认后再次提交 | 回执可查、写入幂等 | 同一会议产生重复待办 |

评测者先看输出及证据，按预先约定的标准评分，不能临时根据模型表现改变标准。若不同专家对政策解释有分歧，应记录分歧来源，补充领域说明或将样本归入待裁决集合。把所有分歧直接多数表决，会掩盖政策本身的不清楚。

对会议中的“下周看看是否安排讨论”，系统最多提取一个待确认事项。把它变成“下周五发送方案”增加了日期、动作与承诺，均缺少文本依据。这里适合使用字段级检查，再对整段草稿进行专家审查。只算纪要与原文的文字相似度，容易让这种错误通过。

## 证据关联比引用数量重要

问答输出可以记录结论 ID 与证据片段 ID 的对应关系。评审时逐条核对证据是否支持该结论，并检查来源是否在有效期内。来源相关性与结论支持度需要分别评分，一份标题相关的文档可能完全没有证明答案中的具体数字。

若系统先检索到正确材料再生成错误答案，优先查看上下文截断、引用拼接和提示约束。如果材料根本没有进入候选集，应检查索引、权限过滤和查询构造。修复检索故障时只修改生成提示，往往没有作用；相同答案失败也可能来自不同路径，因此测试记录必须保留必要轨迹。

敏感信息不宜全部写入通用调试日志。可以记录文档 ID、版本与片段摘要哈希，在受控环境中授权回读原文。哈希不能代替访问控制，也不能阻止猜测短文本内容；它只用于核对引用对象是否变化。

## 人工复核与写入的边界

一个教学流程可以设为草稿生成、顾问修改、确认预览、权威系统写入、回执核对。每次确认都绑定当前草稿版本。用户确认后又改了行动负责人，旧确认失效。会议与客户记录的关联也要独立检查，不能根据人名相似度直接选择客户账户。

用户修改文字时记录修改类型。删除没有依据的承诺进入严重错误回归集；调整礼貌措辞进入表达偏好集；补充会议之外的新事实需要重新标注来源，不能回填为模型从原始会议正确提取的结果。反馈的使用目的与访问权限应在收集前确定。

## 回归报告怎样形成发布决策

本书设定一个完全合成的比较练习。旧版在四十条问答中答对三十四条，新版答对三十六条。平均结果增加了两条，但新版在一个敏感权限样本中泄露资料。仅按总分，新版看起来更好；按严重错误的独立发布门槛，新版不能发布。四十条样本也无法证明面对全部业务输入的成功率。

比较两个版本时使用相同样本，并记录哪些样本由错变对、哪些由对变错。若样本共享同一文档或同一会议，不应简单假设所有观测完全独立。第 9 章讨论置信区间与切片，本章的重点是把统计结果交给有权作发布决定的人。

## 读者实作与复盘

写一段包含明确行动、模糊计划与否定承诺的合成会议文本，分别列出允许输出与禁止输出。再写一条政策问答，让正确答案依赖一个例外条件。为每条样本指定评审人、严重程度和证据。

答案应保留模糊计划的不确定性，不把否定句中的动作当成承诺；政策回答应带上影响结论的例外。若评审人无法达成一致，先修正样本说明或确认业务政策，再继续调模型。

## 可复用的 FDE 工作包

准备两套分别面向问答与会议的评测表，定义严重错误、人工确认与写入规则。用模拟材料完成「草稿、复核、确认、写入」的演练，检查取消和重复提交两条路径。

## 资料没有说明什么

客户故事没有提供完整评测集、所有阈值、成本与独立对照。公开方案也不构成对金融机构数据或业务合规的通用承诺。
