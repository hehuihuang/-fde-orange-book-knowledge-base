# 第 7 章　RAG 与企业知识

RAG 是检索增强生成。应用先从允许访问的资料中找出相关证据，再让模型根据证据回答。它适合资料会更新、答案需要出处的任务，但效果依赖整条数据处理过程。

## 从文档到证据

基本过程是收集与授权、解析、切分、建立索引、检索、排序，再生成答案与引用。每一步都可能改变结果。扫描件识别错了一位数字，检索再准确也无法恢复原始事实。

切分时要保留理解片段所需的背景。孤立的一行表格可能缺少列名，条款可能缺少适用范围。片段应关联文档标题、章节、版本、日期和权限。补充背景可以帮助检索，但补充内容也需要检查，不能悄悄改变原文含义。

## 检索方法按任务比较

关键词搜索擅长精确名称、编号和专业术语；向量检索擅长表达不同但语义接近的查询。混合检索与重排序可以作为候选方案，用真实问题比较后决定是否采用。

不要只测答案。先看正确资料是否进入候选结果，再看它是否被排在可用位置，最后检查模型是否正确使用。若第一步已经失败，继续修改回答提示通常不会解决问题。

| 失败现象 | 优先检查 |
| --- | --- |
| 完全找不到资料 | 是否入库、解析是否完整、权限是否正确 |
| 找到同名旧文件 | 版本、生效时间与排序 |
| 引用存在但不支持结论 | 片段完整性和答案证据匹配 |
| 不同用户看到相同敏感内容 | 检索过滤、缓存隔离与引用权限 |

## 知识需要维护人

每类重要资料都应有所有者。新增、修订、撤回和失效需要明确流程。删除或撤回源资料时，索引、缓存和引用也要按组织政策同步处理，避免旧内容继续出现在回答中。

没有足够证据时，可以展示检索结果并提示无法得出结论。拒答不必意味着页面什么都不提供，但不能为了完整感而编造规则。

## 本章练习

建立一组包含编号查询、口语查询、过期规则和越权问题的测试集。分别记录检索命中、引用正确和答案可用三项结果。先修复最前面失效的一步，再比较整体表现。
