# 第 8 章　工作流、Agent 与 MCP

一个应用可以使用模型，却不需要让模型决定所有步骤。把流程控制交给谁，是工程设计中必须明确的选择。

## 固定工作流与动态决策

工作流由程序预先安排步骤。例如先识别单据，再校验字段，最后交给人工确认。Agent 则可以根据当前结果决定下一步动作，例如先查询订单，发现缺少配送信息后再调用物流工具。

Anthropic 的工程文章采用这一划分，并建议从简单、可组合的方法开始。它适合解释设计取舍，不能被理解为一种必须追求更高自主性的成熟度排名。

| 任务条件 | 可先考虑的方案 |
| --- | --- |
| 规则确定、字段明确 | 普通程序与规则引擎 |
| 步骤固定、部分步骤需要理解语言 | 带模型节点的工作流 |
| 路径随输入变化、结果可以检查 | 有边界的 Agent |
| 多个独立子任务且收益可验证 | 并行或多 Agent，额外评估协调成本 |

## 工具决定行动范围

工具说明要让调用者知道何时使用、需要什么参数、返回什么，以及会改变什么状态。给 Agent 一个可任意执行的通用接口，往往会把本来能够限制的风险放大。

控制至少包括调用次数、总运行时间、费用预算和写入权限。停止条件要由程序执行，不能只在提示里要求模型自觉遵守。外部页面和工具返回内容都可能含有不可信指令，不能自动升级为系统授权。

## MCP 解决连接约定

MCP，即 Model Context Protocol，规定 AI 应用与外部服务交换上下文和调用能力的方式。常见角色包括宿主应用、客户端和服务器。服务器可以提供工具、资源与提示模板。

协议统一了部分连接方式，但不会自动替应用选择正确工具，也不会替企业完成权限设计和安全审查。接入一个服务器以前，仍要核对它能访问的数据、能执行的动作、凭据范围和维护来源。协议版本变化较快，实施时应使用当前官方文档。

## 本章练习

为一个只读查询任务设计两个工具。每个工具写出参数、结果、错误和权限。再加入一个写工具，说明它为什么需要确认，以及用户取消后系统应保留什么状态。最后检查是否能用固定工作流更简单地完成同一任务。
