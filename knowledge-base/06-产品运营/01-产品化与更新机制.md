# 产品化与更新机制

数字资料能持续卖，依赖清楚的读者任务、可信来源和稳定更新。页数很容易被复制，难以形成长期优势。买家需要快速定位、拿来就用，并知道哪些事实已经过期。

## 产品层级

基础包可以包含橙皮书 PDF、案例库和模板。进阶包可以增加月度更新、案例讲解和项目评审清单。企业包可以提供内部使用授权、行业化模板和更新记录。定价要与更新和售后成本匹配，不承诺无限咨询。

## 每月更新

第一周检查官方 FDE 岗位和主要平台变化。第二周复核案例企业是否发布新结果或反例。第三周检查 GitHub 仓库维护、安全公告和许可证。第四周发布变更记录，标出新增、修正、过期和待核实。

重大更新包括法规变化、案例结果被后续文件修正、岗位职责明显变化、核心 GitHub 项目归档和安全事件。重大变化直接修改正文，并在 Changelog 写来源和影响。

## 售卖页应写清

- 适合谁，解决哪三个任务。
- 文件格式、目录、案例和模板数量。
- 研究截止日期和更新频率。
- 个人与企业内部使用边界。
- 案例数字来自公开披露，不构成收益承诺。
- 哪些服务不包含在购买中。

## 质量底线

链接可打开，内部导航无断链。案例有证据等级、来源和资料缺口。模板没有虚构示例数据。版本号、日期和更新记录一致。销售文案不使用官方、认证、唯一、保证就业或保证收益等无法证明的表述。
