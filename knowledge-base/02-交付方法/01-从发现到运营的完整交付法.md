# 从发现到运营的完整交付法

FDE 项目经常从一句宽泛要求开始。客户想要一个智能助手，领导想让团队使用 AI，业务部门想把慢流程自动化。工程师若立刻画架构，往往会把最容易演示的部分做得很好，把权限、例外和责任留到最后。

这套方法把项目分成六段。每一段都要留下可复核证据，满足退出条件后再进入下一段。

## 一　进入现场

### 要完成的事情

跟着真实用户完成任务。记录触发条件、输入、系统、判断、交接、例外和最终结果。至少观察一个普通案例和一个失败案例。访谈管理者能知道目标，观察一线人员才会看到复制粘贴、电话确认和纸面绕法。

### 最低交付物

- 一句话问题陈述。
- 当前流程图和系统清单。
- 决策人、操作人、审查人和受影响人。
- 任务量、处理时间、返工、错误和业务后果的基线。
- 数据、权限、合规和组织风险假设。

### 退出条件

团队能拿一个真实样本，从触发走到结果。流程所有者愿意承担试点结果。关键数据有合法入口，不能获得的数据已经写进限制。

## 二　选择用例

把候选任务同时放进价值、频率、AI 适配、数据准备、风险和所有者投入六个维度。没有所有者、没有可用数据或高风险无法控制的任务直接暂停，不用总分掩盖否决项。

第一批用例适合满足四个特征。工作重复发生，结果可以检查，失败可以发现或撤回，用户愿意每周测试。用例越窄，越容易把整个责任链跑通。

### 价值契约

价值契约应写清基线、目标、不可恶化指标、试点人群、时间、验收方法和停止条件。节省时间要说明节省的是哪一步，质量要说明由谁判断。没有测量方案的收益只算假设。

## 三　做真实薄切片

薄切片要穿过身份、数据、模型、工具、日志和用户入口。它可以只支持一种任务，不能依靠演示者手工准备。第二个迭代就应进入影子模式，让系统处理真实流量但不影响业务结果。

### 技术合同

| 层 | 需要写清的内容 |
| --- | --- |
| 身份 | 用户、服务账号、租户、权限继承和审计身份 |
| 数据 | 来源、所有者、新鲜度、允许用途和保留周期 |
| 模型 | 任务、版本、输入输出、替代路线和预算 |
| 工具 | 读写权限、参数校验、幂等、超时和确认 |
| 人工 | 何时复核、谁能批准、怎样升级和申诉 |
| 运行 | Trace、指标、告警、降级、回滚和支持 |

## 四　把评测变成规格

评测集来自真实任务、历史失败、边界、恶意输入和高风险样本。开发集用于快速改进，保留集用于发布前判断。不要在同一批样本上反复调试后又把它当独立证明。

评分分为确定性检查、专家量表、模型评分和生产结果。能用代码判断的格式、工具参数和权限先用代码。主观质量由领域专家给清晰量表。模型评分器要用人工样本校准。生产结果负责检验离线分数是否真的转成业务价值。

评测详情见 [Evals 与发布门禁](02-Evals与发布门禁.md)。

## 五　受控上线

上线顺序通常从建议、预览、确认执行走到有限自动执行。高风险动作保留人工。灰度按用户、地区、任务或风险分组，避免一次把所有变量一起改。

上线清单至少包含数据迁移、权限测试、容量、成本、监控、告警、值班、降级、回滚、培训和支持入口。业务负责人签署范围，安全和合规人员签署控制，工程负责人确认运行准备。

### 运行门槛

- 核心评测和高风险切片达标。
- 关键工具通过权限、幂等和失败测试。
- Trace 能还原一次完整任务。
- 预算、延迟和容量压测完成。
- 人工升级和手工流程实际演练。
- 回滚不依赖某一位工程师在线。

## 六　运营、交接和复用

生产第一周每天看失败样本，随后按风险改成每周或每月。模型、提示、知识源、工具和政策任一变化都可能触发回归。团队需要同时观察业务结果、采用、系统质量和人工负担。

交接从第一天开始。客户团队要会看监控、处理事件、更新知识、调整允许配置和训练新人。FDE 个人长期掌握所有隐性信息，说明交付没有结束。

复用按证据升级。第一例写清做法，第二例比较差异，第三例再决定是否做成组件或产品默认。复用资产必须有适用边界、版本、测试和所有者。

## 每周交付节奏

| 节点 | 内容 |
| --- | --- |
| 周一 | 看生产样本、风险和本周唯一目标 |
| 周中 | 与真实用户一起跑任务，记录分歧和新例外 |
| 发布前 | 跑评测、风险切片、成本和回滚检查 |
| 周末 | 展示真实结果，更新决策、风险和下周范围 |

会议不替代证据。每周至少要有一项系统变化、一组真实样本或一个被明确推翻的假设。
