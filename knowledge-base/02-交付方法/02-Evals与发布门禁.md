# Evals 与发布门禁

企业 AI 系统的规格很少能全部写成确定规则。模型输出有概率，知识会更新，用户语言和工具状态也会变化。Evals 把“这次改动有没有更好”从感觉变成可以重复检查的问题。

## 先确定评测单位

单轮回答适合查事实、格式和引用。完整任务要看多轮上下文、工具选择、状态变化和最终结果。Agent 项目至少保留 turn、trace 和 task 三层记录。只给每条模型输出打分，会漏掉重复调用、错误写入和中途升级。

## 样本怎样来

- 真实历史任务经过脱敏后进入候选集。
- 领域专家补常见边界和罕见高风险事件。
- 生产失败经过复盘后进入回归集。
- 红队补提示注入、越权、数据泄露和工具滥用。
- 合成样本用于补覆盖，不能替代真实分布。

每条样本写用户任务、上下文、允许工具、成功条件、禁止行为、风险等级和来源日期。

## 四种评分器

### 代码评分

检查 JSON、字段、数值、引用存在、工具参数、权限、状态和延迟。它稳定、便宜，能用代码判断的内容优先放这里。

### 领域量表

专家判断事实是否正确、建议是否适用、关键遗漏是否危险。量表用可观察行为描述一分、三分和五分，避免只写“差、一般、好”。

### 模型评分

适合大规模预筛和语言质量。先用人工标注集计算一致性，定期检查漂移。高风险结论不能只由同一家模型给自己打分。

### 生产结果

任务是否完成、用户是否采纳、是否重复联系、人工是否接管、业务指标是否改变。生产结果最接近价值，也最容易受其他因素影响，需要与版本和人群绑定。

## 发布门禁怎样写

门禁不只写平均分。每项需要总体阈值、高风险阈值、关键切片和不可恶化指标。

```yaml
release_gate:
  task_success_min: 0.90
  citation_support_min: 0.97
  unsafe_action_max: 0
  high_risk_recall_min: 0.99
  p95_latency_ms_max: 8000
  cost_per_task_usd_max: 0.20
  no_regression:
    - permission_enforcement
    - human_escalation
```

数值是模板示例，不是通用行业标准。真实阈值由业务损失、人工接管能力和法规共同决定。

## 版本比较

一次只改一个主要变量。模型、提示、检索、工具和政策同时改变，失败后很难定位。比较报告保留样本级差异，按失败类别审查，不只看总分。

新版本先离线，再影子，最后灰度。生产触发回归的事件包括模型升级、提示变更、知识源大改、工具接口更新、政策更新和事故。

## 常见失真

评测集太干净会让生产边界消失。专家知道标准答案，真实用户却会少给字段、混用缩写或改变目标。模型评分器偏好流畅语言，可能放过没有证据的答案。只保留成功样本，系统就学不会拒答和升级。

每月从生产随机抽样，并刻意寻找高成本失败。评测集需要版本和保留集，不能让所有样本都变成开发材料。
