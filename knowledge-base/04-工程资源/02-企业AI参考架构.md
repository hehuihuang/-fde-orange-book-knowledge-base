# 企业 AI 参考架构

参考架构用于检查漏项，不要求所有项目照搬。一个窄任务可以很简单，只要身份、数据、模型、工具、人工和运行责任仍然清楚。

## 请求路径

```text
用户或业务事件
  -> 身份、租户与风险判断
  -> 工作流编排
  -> 检索和业务数据
  -> 模型与策略路由
  -> 工具预览或执行
  -> 人工确认或升级
  -> 业务系统写入
  -> Trace、指标、评测与反馈
```

## 七个边界

身份边界决定用户能代表谁。数据边界决定模型能看什么。模型边界决定哪些判断可以概率化。工具边界决定系统能改变什么。人工边界决定谁承担最终责任。运行边界决定故障怎样降级。反馈边界决定生产数据怎样进入改进。

## 版本对象

生产 Trace 至少绑定模型、提示、检索索引、工具、策略和知识源版本。只记录模型名无法解释结果变化。部署报告要能比较版本并定位是哪一层改变。

## 预算与延迟

上下文按任务价值分配。先放规则、当前状态和关键证据，再补历史。对话越长不等于答案越好。缓存、检索、模型调用和工具分别计时，才能知道优化哪一段。

## 多模型

多模型用于满足不同质量、延迟、数据驻留或可用性要求。它会增加评测、故障语义、供应商治理和观测成本。每条路由都要有任务理由和回退条件。
