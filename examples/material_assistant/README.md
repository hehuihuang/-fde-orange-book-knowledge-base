# 第 27 章伴随工程

这是本书原创的离线物料与采购教学工程。数据、租户、姓名、供应商与预算全部合成。它通过 Python 标准库和内存 SQLite 展示带权限的检索、记录级证据、物料专属单位换算、采购草稿、审批摘要绑定、幂等确认、预算事务与成功事件审计。

程序没有调用大模型、网络、真实 ERP 或供应商。`run_demo()` 使用预设编排顺序，检索使用确定性规则。不要把它当作已经具备自然语言规划能力的生产 Agent。真实模型可接在提案层，服务端校验与写入规则应当保留。

## 运行

从仓库根目录运行，Python 3.10 或更新版本即可，不需要额外安装包。

```bash
python3 examples/material_assistant/material_assistant.py
python3 -m unittest discover -s examples/material_assistant -v
```

第一条命令打印完整 JSON，不写入文件。每次运行都会在内存重新建立合成数据，因此预算恢复到初始的 100000 分。订单和审批标识随机生成，演示时间取当前系统时间，这几项输出不会逐字一致。

## 观察结果

搜索 `6305` 返回两个同型号、不同材料与密封方式的候选。`needs_clarification` 应为 `true`。演示随后模拟使用者明确选择碳钢物料 `BR-6305-CS`。

它创建一盒采购草稿。这种物料一盒含十个，基础单价为 2500 分，所以草稿总额为 25000 分。不锈钢候选一盒含五个，不能沿用这个换算。

另一名合成用户批准相同草稿摘要，申请者确认后生成一张本地教学订单。预算余额变成 75000 分。相同幂等键再次确认应返回相同订单标识，`replayed` 为 `true`，预算保持不变。

这一张本地订单代表教学程序内的确认记录。它没有触发采购、支付、库存扣减、真实库存预留或外部 API。

## 实测记录

2026 年 9 月 18 日，本项目执行了上述演示和 31 项 `unittest`，全部通过。该记录证明本地代码在这些合成输入上的行为，不能证明真实模型质量、生产吞吐、真实采购节省或企业安全合规。

首次测试时，同型号澄清用例和完整演示用例失败。碳钢物料因别名获得额外排序分，旧规则把排序差距当作自动选择的依据。修复后，同型号多候选会独立触发澄清，不受排序分差影响。测试保留了全角型号输入和这组同型号数据，防止修复退化。

## 文件与主要接口

| 文件或接口 | 作用 |
| --- | --- |
| `material_assistant.py` | 数据结构、合成数据、服务与演示 |
| `test_material_assistant.py` | 31 项可执行不变量测试 |
| `search` | 先按租户和品类过滤，再排序 |
| `answer` | 从具体记录构造有版本依据的回答 |
| `create_draft`、`update_draft` | 创建和修改草稿，服务端计算金额 |
| `preview` | 返回可显示的完整有效负载和摘要 |
| `approve` | 独立审批者授权特定摘要，限时有效 |
| `confirm` | 复核权限、版本与预算，事务写入并记录幂等回执 |
| `audit_events` | 获授权审批者读取本租户成功事件 |

## 信任边界

示例没有实现登录、HTTP、会话、签名或令牌验证。接口中的 `tenant` 和 `user` 代表由可信认证层注入的身份上下文。它们不能直接接受浏览器表单、模型文本或未核验请求的自报身份。不同租户可以存在同名用户，修改这两个参数相当于更换被模拟的身份，不等于攻击者能够合法切换租户。

跨租户测试验证对象查询、候选排序、草稿确认和审计读取都以已注入租户为边界。部署时还必须证明认证层把这个边界固定在经过核验的会话上。

摘要使用固定 JSON 编码与 SHA-256，作用是发现内容变化。摘要不能证明审批人身份，也不能抵抗同时修改数据库正文、摘要和授权记录的特权攻击者。审批权限来自数据库中的角色、范围和有效状态。

成功的订单、预算变更、幂等回执和成功审计事件在一个 SQLite 事务内提交。演示会把订单失败前的事务变更回滚。失败请求尚未写入独立安全日志。审计表也没有防篡改签名、外部日志接收器或保留期管理。

## 有意简化的部分

示例只支持单物料草稿、整数数量、单一币种和维护好的整数包装换算。没有小数重量、汇率、税费、运费、多明细审批、多级审批或审批委托。预算只是合成租户中的剩余额度，不等于真实财务预算制度。

没有库存预留、供应商下单、ERP 同步、消息队列或分布式事务。多个真实服务和外部系统需要另行设计持久化幂等、外部业务键、发件箱和对账机制。31 项测试未覆盖多进程竞争、故障恢复、进程重启后的持久化或真实模型行为。

不要直接把本项目公开为生产 API。先完成认证接入、数据合同、授权回归、外部写入协议、失败日志、备份恢复和业务验收。
